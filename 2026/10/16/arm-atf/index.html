ARM ATF

2026-10-16 · ARM/ATF

一、ATF 是什么

ATF = ARM Trusted Firmware (现称 TF-A)
它是 ARM 定义的一套安全启动与运行时固件规范，它由多个独立固件模块组成，分别运行在不同异常等级（EL）上，分工不同。所以：

  • 规范层面：ATF 定义了 BL1、BL2、BL31、BL32、BL33 这套启动链和接口；
  • 实现层面：ATF 项目提供了 BL1、BL2、BL31 的代码，以及可选的 BL32（如 OP-TEE）；
  • BL33 通常不属于 ATF：BL33 一般就是 U-Boot，是独立项目

一句话定位：Linux 想做但没权限做的事（开核、断电、复位、切世界），全部通过 SMC 交给 ATF 完成。

二、异常等级与安全世界

异常等级（Exception Level，EL） 是 ARMv8-A 架构引入的一个特权层级概念，用来划分代码运行时能访问的硬件资源和能执行的指令，核心目的是隔离与安全

2.1 四个异常等级

EL 名称 运行内容 权限
EL0 非特权 用户态应用程序 最低，不能访问系统寄存器、不能执行特权指令
EL1 特权 操作系统内核（Linux、OP-TEE） 能管理内存、中断、进程
EL2 虚拟化 KVM / Hypervisor 能虚拟化、管理多个 OS
EL3 安全监控 安全监控固件（ATF 的 BL31） 最高，负责安全世界与非安全世界切换

2.2 安全世界与非安全世界

安全世界 和 非安全世界 是 ARMv8 在 CPU 内部划出的两个并行运行环境。它们共享同一颗芯片，但彼此隔离。
目的：保护敏感操作，如指纹识别、人脸识别、移动支付、DRM 版权保护、密钥存储、加密运算等等。
这些操作如果放在普通 Linux 里，一旦内核被攻破，密钥和指纹数据就泄露了。所以 ARM 把它们放到一个隔离的、普通世界无法访问的环境里运行。

关键点：

  • 两个世界可以同时存在，CPU 可以在两者之间切换；
  • 非安全世界不能访问安全世界的内存和外设；
  • 安全世界可以访问非安全世界的资源（权限更高）。

三、启动阶段 BL1 → BL33

3.1 两种视角下的启动链（对比图）

左边是 U-Boot 视角（BootROM → SPL → U-Boot → Kernel），右边是 ATF 视角（BL1 → BL2 → BL31 → BL32 → BL33 → Kernel）。

它们描述的是同一段上电过程，只是切分与命名不同：

3.2 各阶段职责

BL1（Trusted Boot ROM Firmware）

  • 位置：芯片 ROM 或 SRAM，芯片出厂后不可改，是信任根的一部分
  • 做最小的初始化：异常向量、CPU 特定 errata、串口（调试用）、SRAM
  • 从存储（eMMC/NAND/SPI-NOR）加载 FIP 中的 BL2 并验签
  • 决定后续是冷启动还是 warm reset 路径（warm boot 走 CPU 上电分支）

BL2（Trusted Boot Firmware）

  • 跑在 Secure-EL1，初始化 DDR、存储控制器、时钟等“重活”
  • 从 FIP 里加载 BL31 / BL32 / BL33 到各自的目标地址
  • 建立页表（xlat tables）、传递参数（bl_params）
  • 验签每一级镜像（CoT 的一环）

BL31（EL3 Runtime Firmware）

  • 唯一常驻到运行时的阶段，永远不退出，提供 Secure Monitor
  • 初始化 EL3 运行时环境：异常向量、上下文管理、SMC 分发框架
  • 注册运行时服务（std_svc 的 PSCI、厂商 SiP、SDEI 等）
  • 初始化 BL32（SPD 负责），然后 eret 到 BL33

BL32（Secure-EL1 Payload，可选）

  • 常见是 OP-TEE，也可以是 TSP（TF-A 自带的测试安全载荷）或 SPM
  • 由 SPD（Secure Payload Dispatcher，如 opteed/tspd）负责加载与后续的世界切换
  • Normal World 通过 SMC 进入 Secure World 的服务（如密钥、DRM、指纹）

BL33（Non-trusted Firmware）

  • U-Boot / UEFI，也可以是直接是 Linux（TF-A 支持 BL33=kernel）
  • ATF 把控制权交给它后，就只剩「被调用」的角色（SMC 进来才执行）

3.3 FIP（Firmware Image Package）

把各阶段镜像打包成一个容器的工具叫 fiptool：

  • 每个镜像带 UUID，BL2 按 UUID 从 FIP 里取
  • 证书/签名由 cert_create 生成（可信启动时使用）

四、BL31 运行时服务框架

4.1 三类服务

类型 OEN 说明
Standard Service（std_svc） 0x4 PSCI、SDEI、TRNG、SPM 等 Arm 标准定义的服务
SiP Service 0x2 芯片厂商私有（MTK、QCOM、Rockchip 各种私有 SMC）
OEM Service 0x3 设备厂商私有

注册方式：

新增一个自己的 SMC 服务，就是照抄 services/std_svc/ 的套路加一个 DECLARE_RT_SVC。

4.2 SMC 处理路径

要点：

  • handler 里不能睡眠、不能做复杂业务，要快
  • 需要跨世界传数据时走共享内存（smc 只传 64bit 参数 x0~x7）
  • 返回值约定：成功返回正数语义，失败返回负的错误码（PSCI 用 PSCI_E_INVALID_PARAMS 等）

五、SMCCC（SMC 调用约定）

5.1 Function ID 格式

举例：PSCI_VERSION = 0x84000000

Fast vs Yielding：

  • Fast Call：原子、不可中断，用于短平快操作（如 CPU_ON、PSCI_VERSION）
  • Yielding Call：可被中断，用于耗时/可阻塞的服务（如 Trusted OS 的调用）

5.2 寄存器约定

  • 入参：x0 = FID，x1~`x7` = 参数（SMC32 只用低 32 位，高 32 位必须清零）
  • 返回：x0 = 状态/返回值，x1~`x3` 可选
  • x8~x17、x29、x30、SP 等由被调用方（EL3）负责保存，Normal World 不用管
  • Linux 侧封装在 include/linux/arm-smccc.h：arm_smccc_smc(fid, a1..a7, &res)

内核里更常见的是直接走 psci_ops（drivers/firmware/psci/psci.c）。

回调 作用

6.3 power domain 拓扑

  • 用 MPIDR 的 affinity0/1/2/3 描述层级：PLAT_MAX_PWR_LVL
  • ATF 的 psci 层负责「最后一个核」判断：只有某 level 上的所有核都下电，才调用该 level 的 pwr_domain_off/suspend
  • 这正是 genpd「域内最后一个设备 suspend 才断电」思想在 CPU 侧的对应

七、ATF 与 Linux / U-Boot 的接口

7.1 设备树中的 psci 节点

  • 内核 psci_dt_init() 解析它 → 决定用 arm_smccc_smc 还是 arm_smccc_hvc
  • 缺这个节点 → psci: probing for conduit method from DT failed，内核拿不到 psci_ops，开核和休眠全废

7.2 内核侧注册

drivers/firmware/psci/psci.c：

唤醒时 ATF 用 CPU_ON(mpidr, entry) 里那个 entry 地址把核拉起来，Linux 侧对应的就是 secondary_entry / cpu_resume。

7.3 U-Boot 侧

  • U-Boot 作为 BL33 被 ATF 拉起，靠 设备树 与 ATF 约定（U-Boot 的 armv8 启动代码处理从 EL3/EL2 降到 EL2/EL1）
  • U-Boot 里也有 psci 命令/驱动，用于自己开核
  • 关键：BL31 和 BL33 的地址、入口、设备树地址必须匹配，否则卡在跳转处无输出

八、安全启动（TBBR / CoT）

8.1 信任链（Chain of Trust）

  • ROTPK：Root of Trust Public Key，芯片出厂烧死
  • 每一级加载下一级前都做签名校验，失败就停机/进恢复模式
  • 反回滚：TRUSTED_BOARD_BOOT + anti-rollback counter，禁止刷回旧版本

8.2 关键编译开关

  • TRUSTED_BOARD_BOOT=1：BL1/BL2 打开验签
  • GENERATE_COT=1：用 cert_create 生成证书链，fiptool 打包进 FIP

九、代码结构速查

想改电源行为 → plat/<vendor>/... 的 plat_psci_ops.c
想加私有 SMC → services/std_svc/ 或 plat 下加 DECLARE_RT_SVC
想看为什么唤醒失败 → lib/psci/psci_main.c + plat 的 suspend_finish

十、编译与调试

10.1 编译

  • LOG_LEVEL：10 ERROR / 20 NOTICE / 30 WARNING / 40 INFO / 50 VERBOSE
  • DEBUG=1 会带上断言、更多日志、crash 输出
  • make help / make PLAT=xxx help 可看平台支持的所有选项

10.2 调试手段

  • 串口日志：最核心。卡在哪一级，看最后一行 log 就知道
  • crash console：ATF 崩溃时 plat_crash_console_flush() 强行刷串口
  • 常见现象与定位
    现象 通常原因
    完全无 log 串口基址/时钟配置错、BL1 就挂了
    BL2 后无输出 DDR 初始化失败、FIP 里镜像地址冲突
    BL31 后无输出 BL33 入口地址错、U-Boot 串口配置与 ATF 不一致
    SMC 返回 unknown/not supported 该 OEN 服务没注册，或 FID 拼错
    唤不醒 validate_ns_entrypoint 校验不过、resume 入口没传、plat 的 suspend_finish 没恢复时钟/内存
    开核卡死 pwr_domain_on 没释放复位、没写正确的 entry

十一、面试常问

  • ATF 有哪几个阶段，各自做什么？ BL1 加载 BL2；BL2 加载 BL31/32/33；BL31 常驻提供运行时服务；BL32 是 OP-TEE（可选）；BL33 是 U-Boot
  • 为什么 Linux 开核要发 SMC？ 因为电源控制寄存器是 Secure 资源，NS-EL1 无权访问，必须 EL3 代理，PSCI 就是这套标准接口
  • SMC 的 FID 怎么编码？ bit31 fast/yielding、bit30 64/32、bit29:24 OEN、bit23:0 function number
  • fast call 和 yielding call 区别？ fast 原子不可中断、用于短操作；yielding 可被中断、用于可能阻塞的安全服务
  • ATF 和 OP-TEE 什么关系？ ATF 在 EL3 负责世界切换与监控，OP-TEE 在 S-EL1 提供可信服务；ATF 通过 SPD 加载并调度 OP-TEE
  • CPU_ON 之后核从哪里开始执行？ 从 OS 传入的 entry point（secondary_entry），ATF 会给它设置好上下文并 eret 到 NS-EL1/EL2
