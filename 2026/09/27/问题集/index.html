问题集

2026-09-27 · 面试

一、C 语言

  1. volatile 的作用与使用场合？
    禁止编译器把变量缓存到寄存器或优化掉"冗余"读写，保证每次都真正访问内存。用于 MMIO 寄存器、被中断或线程修改的共享标志。它不保证原子性。
  2. static 修饰局部变量、全局变量、函数时的区别？
    局部变量：改为静态存储期，只初始化一次，作用域不变。全局变量与函数：限定链接域为当前文件，避免命名冲突、隐藏实现细节。
  3. const int *p / int * const p / const int * const p 的区别？
    分别是"指向常量的指针"（值不可改、指针可变）、"常量指针"（指针不可改、值可变）、"都不可改"。判断口诀：从右往左读，const 修饰它左边最近的东西；如果左边没有，就修饰右边。
  4. 结构体内存对齐规则？如何计算结构体大小？
    成员起始地址必须是其自身对齐数的整数倍，结构体总大小再向上取整为最大成员对齐数的整数倍。可用 `__attribute__((packed))` 或 `#pragma pack` 改变，代价是访问效率与兼容性。
  5. sizeof 与 strlen 的区别？
    `sizeof` 是编译期运算符，算类型或对象占的字节数（含结尾的 '\0'）；`strlen` 是运行期函数，遇到 '\0' 停止。数组名 `sizeof` 得到整个数组，退化为指针后只剩地址宽度。
  6. 宏函数与普通函数的优劣？多语句宏为什么用 do{}while(0)？
    宏省调用开销、不检查类型因而通用；缺点是无类型检查、易因缺括号或参数副作用出错、无法调试。`do{}while(0)` 把多条语句包装成单条语句，可在 if/else 后安全加分号，还提供独立作用域。
  7. container_of 的实现原理？
    用成员地址减去 `offsetof(结构体类型, 成员)` 得到宿主结构体首地址再强转。内核据此从嵌入成员反查外层对象，如由 cdev 找到自己的设备结构体。
  8. 大小端如何判断与转换？
    小端低字节存低地址（x86/ARM 常见），大端相反。判断可用联合体或强转 char 指针读首字节；转换一般用 htonl/ntohl 族，或手写位拆分组合。
  9. 位运算实现置位、清位、取位的写法？
    置位 `reg |= BIT(n)`；清位 `reg &= ~BIT(n)`；取连续位域 `(reg & GENMASK(h,l)) >> l`。内核推荐 `FIELD_GET/PREP`，避免手算掩码出错。
  10. 内存泄漏、野指针、越界如何定位？常用检测手段？
    用户态用 valgrind、AddressSanitizer；内核态用 kmemleak 查泄漏，KASAN、SLUB debug（redzone/poison）查越界与 use-after-free，野指针多靠 oops 地址反查。
  11. #define 宏与 inline 函数的区别？
    宏在预处理阶段做文本替换，无类型检查、无作用域、可被 undef，参数还可能有副作用；inline 由编译器处理，有类型检查与作用域，遵循函数语义，可调试。两者都可能省掉调用开销，但 inline 只是建议，编译器可能不展开；为语义清晰，优先用 static inline。
  12. 为什么需要字节对齐？对齐的本质原因是什么？
    CPU 按总线宽度成块取数据，未对齐访问要么被拆成多次访存（性能损失），要么直接触发对齐异常；此外原子操作、向量指令与 cache line 访问都要求地址对齐。因此对齐是硬件访问粒度与原子性共同决定的约束。

二、Linux 基础

  1. 用户态与内核态的区别与切换方式？
    内核态可执行特权指令、访问全部资源；用户态受限，只能访问自己的虚拟地址空间。切换靠三种陷入：系统调用、异常（如缺页）、外设中断。
  2. 系统调用的完整流程？
    glibc 封装 → svc/ecall 指令陷入 → 查系统调用表找到 sys_xxx → 执行 → 返回值写入返回寄存器 → 恢复现场返回用户态。错误时置 errno。
  3. 进程、线程、协程的区别？
    进程是资源分配基本单位，有独立地址空间；线程是调度基本单位，共享地址空间（Linux 同样用 task_struct 描述）；协程运行在用户态，切换不进内核、开销极小，多为非抢占。
  4. 进程间通信方式各自的适用场景？
    管道适合父子进程简单字节流；信号用于异步通知；消息队列保留消息边界；共享内存最快，但需另配信号量或互斥锁同步；信号量做计数同步；socket 支持跨主机与本地 AF_UNIX。
  5. 虚拟内存与物理内存的映射关系？MMU 的作用？
    CPU 只看到虚拟地址，MMU 查页表转换成物理地址，并检查读写执行权限与缓存属性。每个进程有独立页表，因此各自看到独立的地址空间。
  6. 缺页异常的触发与处理流程？
    页表项无效或权限不足时 CPU 触发缺页，进入 do_page_fault：区分匿名页（分配零页或伙伴页）、文件映射（从磁盘读入 page cache）、写时复制（复制新页）、真非法访问（发 SIGSEGV）四类处理。
  7. 动态库与静态库的区别？
    静态库在链接时被复制进可执行文件，运行不依赖外部库但体积大、升级需重编；动态库运行时由加载器映射，可被多进程共享、体积小，但需保证库存在且路径正确。
  8. 文件描述符与 inode 的关系？
    fd 是进程打开文件表的索引，指向 struct file（记录打开实例与读写偏移）；多个 fd 可指向同一 file（dup），多个 file 可指向同一 inode（多次 open）。inode 才是文件本身的元数据。
  9. 同步与异步、阻塞与非阻塞的区别？
    同步/异步关注"结果怎么拿到"，阻塞/非阻塞关注"调用是否立刻返回"。二者正交：同步阻塞 read、同步非阻塞轮询、异步 IO（aio、io_uring）。
  10. select / poll / epoll 的区别？
    select 有 fd 数量上限且每次要重传并全量遍历；poll 用链表突破数量限制但仍要遍历；epoll 用红黑树注册、就绪链表回调，返回即就绪，另有 LT/ET 两种模式差异。
  11. CPU cache 的工作原理？cache line、局部性与伪共享是什么？
    cache 是 CPU 与主存之间的小容量高速缓存，按 cache line（通常 64 字节）为单位搬运，依赖时间局部性与空间局部性提高命中率。由此带来两个问题：一是与外部设备（DMA）或其他核的数据一致性，需要显式 flush/invalidate；二是伪共享，多个核频繁改写同一 cache line 的不同变量会互相失效，需做 cache line 对齐或隔离。
  12. 什么是进程上下文与中断上下文？各自的约束是什么？
    进程上下文是内核"代表某个进程"执行的状态（系统调用或内核线程），有明确的 task_struct，current 有意义，可以睡眠、被调度，也可以与用户空间交换数据（copy_to_user/copy_from_user）。中断上下文是处理中断时的状态，不属于任何任务，因此不能睡眠、不能取 mutex、不能调用可能睡眠的函数，也不可直接访问用户空间地址，只能用自旋锁并要求尽快返回，慢活交给下半部或线程化处理。此外还有软中断/tasklet 上下文，同样不允许睡眠。

三、Linux 驱动

  1. 字符设备驱动的编写流程？
    申请设备号（alloc_chrdev_region）→ 初始化并 cdev_add 注册 → class_create / device_create 生成设备节点 → 实现 file_operations → 退出时反向释放。简单场景可用 miscdevice 简化。
  2. module_init 的调用时机与实现机制？
    宏把函数指针放进 .initcall 段，编译进内核时由 do_initcalls 按级别顺序调用；编译成模块时由 insmod 的装载过程调用该入口。
  3. 设备树的作用？驱动如何与设备树匹配？
    设备树描述硬件资源（寄存器、中断、GPIO、时钟、供电），使硬件改动不必改代码。驱动用 of_match_table 中的 compatible 与节点匹配，再由 of_* API 取具体资源。
  4. platform 总线、设备、驱动三者关系？
    platform 是虚拟总线：platform_device（由设备树生成或代码注册）与 platform_driver 通过 compatible/name 匹配后调用 probe。总线负责"设备与驱动解耦 + 统一匹配"。
  5. probe 函数的职责？
    取资源（寄存器、中断、GPIO、时钟、regulator）、初始化硬件、向内核子系统注册设备、保存 drvdata。remove 做反向释放，失败路径需回退已申请的资源。
  6. copy_to_user / copy_from_user 为什么不能直接 memcpy？
    用户地址属于另一地址空间，内核不能直接解引用；且指针可能非法或未映射。copy_*_user 会做 access_ok 校验，出错返回 -EFAULT 而不是崩内核。
  7. ioremap 的作用？为什么不能直接用物理地址？
    CPU 只认虚拟地址。ioremap 把物理地址区间映射进内核页表（通常带设备内存、非缓存属性），返回可用的虚拟地址。直接用物理地址会触发缺页。
  8. kmalloc / vmalloc / dma_alloc_coherent 的区别？
    kmalloc 物理连续、快但大小有限；vmalloc 仅虚拟连续、可分配大块但不能做 DMA；dma_alloc_coherent 物理连续且保证一致性，适合 DMA 缓冲。
  9. file_operations 中常用成员的作用？
    open/release 管理打开与释放，read/write/llseek 读写数据，unlocked_ioctl 下发自定义命令，poll 支持 select/epoll，mmap 把内核缓冲映射到用户空间；owner 防止模块被意外卸载。
  10. 主设备号与次设备号的意义？设备节点如何创建？
    主设备号标识驱动，次设备号标识该驱动下的具体实例。节点可手工 mknod、由 udev 依据 uevent 自动创建，或用 class_create 加 device_create 生成。
  11. regmap 的作用与优势？
    把 I2C/SPI/MMIO 寄存器访问抽象成统一接口，附带缓存、字节序处理、volatile/precious 标记、寄存器范围检查，还能在 debugfs 直接导出寄存器。
  12. 总线驱动、设备驱动、控制器驱动的分层关系？
    控制器（主机侧）驱动实现总线时序本身；核心层提供统一注册与匹配 API；设备（外设）驱动只关心具体器件逻辑。三者通过总线匹配解耦。
  13. DMA 为什么会有缓存一致性问题？如何处理？
    DMA 直接在内存读写，CPU 看到的可能是 cache 中的旧副本，两边数据不一致。三种处理方式：用一致性内存 dma_alloc_coherent（非缓存或硬件一致性）；用流式映射 dma_map_single/sg 并在 map/unmap 时由框架按方向做 invalidate/flush；在搬运过程中需要访问时用 dma_sync_single_for_cpu/for_device 同步。
  14. DMA 的实现方式有哪些？提升数据吞吐的优化方向？
    实现方式：一致性分配 dma_alloc_coherent、流式映射加 scatter-gather（dma_map_sg）、跨设备共享用 dma-buf，带 IOMMU 时可直接用物理离散页。优化方向：批量搬运而非单包频繁映射、用 SG 聚合减少映射开销、加大缓冲与环形队列、合并中断或改用轮询减少中断次数、按 cache line 对齐避免伪共享、必要时提升 DDR 带宽或总线 QoS 优先级。
  15. probe 时依赖的资源或上游设备还没就绪怎么办？不想在 probe 里等待如何处理？
    不要在 probe 中无超时轮询或长延时死等。若刚好处在资源缺失（时钟、regulator、GPIO、上游供应商设备）阶段，应返回 -EPROBE_DEFER，内核会在依赖就绪后自动重新调用 probe，可查看 /sys/kernel/debug/devices_deferred。若不想拖慢启动：①用 device_link_add 声明供应者-消费者关系，由框架保证 probe 顺序；②probe 只做最小注册，把耗时初始化放到 open/首次访问时的延迟初始化，或交给 workqueue 异步执行；③确实要等待时用带超时的 wait_for_completion_timeout 或轮询加超时，超时返回错误而不是阻塞，注意失败路径的资源回退。

四、并发与同步

  1. 自旋锁与互斥锁的选用原则？
    临界区极短且不能睡眠（含中断上下文）用自旋锁，忙等占 CPU；临界区较长、允许睡眠的进程上下文用互斥锁。
  2. 为什么自旋锁保护的临界区不能睡眠？
    睡眠会让持锁者被调度出去，等待者只能空转占住 CPU，单核上必然死锁。因此临界区内不能调用可能睡眠的函数。
  3. 中断上下文中能用 mutex 吗？为什么？
    不能。mutex 获取失败会让出 CPU，而中断上下文不是可调度实体，一旦睡眠无人把它唤醒，会触发 scheduling while atomic 错误。
  4. spin_lock / spin_lock_irqsave / spin_lock_bh 的区别？
    spin_lock 关闭抢占；_irqsave 保存并关闭本地 CPU 中断，用于与中断上下文共享的数据；_bh 关软中断，用于进程上下文与 tasklet/软中断共享的数据。
  5. 死锁产生的四个必要条件？如何排查死锁？
    互斥、占有且等待、不可抢占、循环等待。排查用 Lockdep 报告、hung_task 检测、sysrq 打印任务堆栈。预防靠统一加锁顺序、避免嵌套、trylock 回退。
  6. 原子操作适用于什么场景？
    简单的计数或标志位的"读-改-写"不可分割场景，开销小且可在中断上下文使用，如 atomic_t、refcount_t、set_bit/test_and_set_bit。
  7. 信号量的使用场景？
    允许指定数量持有者的资源计数场合（如最多 N 个进程同时打开设备）。新代码一般改用 mutex（二值）或 completion（一次性同步）。
  8. 完成量 completion 适用于什么场景？
    一个执行体等待另一执行体完成某件事：等待固件或硬件初始化完成、等待线程退出等。语义比信号量更明确，并支持超时等待。

五、中断

  1. 中断的完整处理流程？
    外设拉中断 → 控制器（GIC）路由到 CPU → 硬件保存现场并跳转向量表 → 通用入口 do_IRQ → 查 irq_desc → 执行 handler（上半部）→ 写 EOI → 返回时执行 pending 的软中断/tasklet。
  2. 上半部与下半部如何划分？
    上半部做最紧急的事：确认中断源、清中断、把数据搬到缓冲、调度下半部，必须尽快返回；下半部处理耗时工作：协议解析、唤醒进程等。
  3. tasklet 与 workqueue 的区别？
    tasklet 基于软中断，同类串行且不能睡眠，适合短任务；workqueue 运行在内核线程上下文，可以睡眠，适合可能阻塞的工作。选择依据就是"是否需要睡眠"。
  4. 中断为什么不能睡眠？
    中断上下文不参与调度，睡眠后没人能把它再调度回来，系统直接死锁。这也是为何中断里只能自旋、不能取 mutex。
  5. 中断线程化解决了什么问题？
    把大部分处理移到可被调度的内核线程，缩短不可抢占区，降低延迟抖动，也是 PREEMPT_RT 的基础形式；用 request_threaded_irq 实现。
  6. 共享中断如何注册？dev_id 的作用？
    request_irq 带 IRQF_SHARED，多个 handler 挂在同一 irq_desc 的 action 链表上逐个调用。dev_id 必须唯一非空，free_irq 时用它定位自己的 action。
  7. 中断号与硬件中断线的映射关系？
    由 irq_domain 把设备树中的硬件中断号（hwirq）映射成内核虚拟中断号。interrupt-parent 指明控制器，#interrupt-cells 定义编码格式（含触发类型）。
  8. GIC 的工作流程？
    Distributor 收集中断、按优先级与亲和性路由；CPU interface 向 CPU 发 IRQ/FIQ；软件读 IAR 取中断号，处理完写 EOIR。中断类型含 SGI/PPI/SPI/LPI。
  9. 电平触发与边沿触发的区别？工程上如何选型？
    电平触发：只要外设中断未被清除就持续有效，因此必须在返回前清掉外设中断源，否则反复重入。边沿触发：只在电平跳变瞬间有效，处理期间来的边沿可能丢失。选型：事件型、脉冲窄且需要保证不丢件(如数据就绪) 适合边沿；状态型、需要保持到软件查询处理、并且exclusive 独占中断的场景适合电平，但电平不要用在共享中断上。
  10. 什么是中断风暴？常见原因与处理手段？
    现象是某 IRQ 计数暴涨、CPU 被占满甚至 softlockup。常见原因：外设中断未被写 1 清除或 EOI 顺序错误、电平一直保持有效、硬件故障拉住引脚、共享中断 handler 返回值错误导致反复 retry。处理：先 cat /proc/interrupts 定位 irq，检查清中断与 EOI、确认设备状态寄存器与极性配置；临时可在 handler 中屏蔽该中断线并转线程化处理；再用 ftrace irqsoff 与 /proc/irq/xx/spurious 辅助定位。

六、总线协议

  1. I2C 为什么要上拉电阻？开漏输出的作用？
    I2C 器件只能拉低不能输出高电平，靠外部上拉提供高电平，从而实现多设备"线与"：任一方拉低即为低。上拉阻值影响上升沿与最高通信速率。
  2. I2C 的起始/停止信号与 ACK 机制？
    SCL 高电平时 SDA 由高变低为 START，由低变高为 STOP；每字节后第 9 个时钟，接收方拉低 SDA 表示 ACK，未拉低即 NACK。
  3. I2C 仲裁与时钟拉伸？
    仲裁靠"线与"：多主同时发送，谁发现自己发的 1 而总线是 0 就退出。时钟拉伸是从机拉低 SCL 延长时间，主机必须支持。
  4. SPI 的四种工作模式如何区分？
    由 CPOL（空闲电平）与 CPHA（第几个边沿采样）组合而成。常用模式 0（CPOL=0, CPHA=0）与模式 3（CPOL=1, CPHA=1），均在上升沿采样、下降沿切换数据。
  5. SPI 与 I2C 的优劣对比？
    SPI 全双工、速率高、靠片选寻址、无应答机制、占用线多；I2C 半双工、有地址寻址与 ACK、只需两根线、速率较低。
  6. UART 的波特率误差容忍度？为什么要过采样？
    UART 无时钟，靠约定波特率；常用 16 倍过采样在比特中部取样。双方波特率偏差累积通常不超过 2%~3%，否则出现帧错误。
  7. RS232 与 RS485 的差异？
    232 单端负逻辑、点对点、距离几十米；485 差分传输、支持多点总线、抗干扰强、可达上千米，多为半双工需要方向控制。
  8. CAN 的仲裁机制与错误检测机制？
    非破坏性仲裁：优先级低的节点发现总线与自己发送不一致就退让，ID 越小优先级越高。错误检测有 CRC、位填充、格式校验、ACK 槽、收发错误计数器。
  9. PCIe 的配置空间与枚举流程？
    软件遍历 bus/device/function，读 Vendor/Device ID 判断是否存在，写全 1 再读回 BAR 得到空间大小并分配，最后按设备 ID 匹配驱动。
  10. USB 设备枚举流程？
    hub 检测电平变化 → 主机复位设备并判别速度 → 用地址 0、端点 0 依次取设备/配置/接口/端点/字符串描述符 → 分配新地址 → 选择配置 → 匹配驱动。

七、存储与启动

  1. 嵌入式系统的完整启动流程？
    上电 → BootROM 读启动模式引脚并加载 SPL 到 SRAM → SPL 初始化 DDR 并加载 U-Boot → U-Boot 初始化外设并加载内核与设备树 → 内核启动用户 init。
  2. BootROM / SPL / U-Boot 各阶段职责？
    BootROM 固化在片内，做最小初始化与安全校验并加载下一级；SPL 负责初始化 DDR 并加载主 U-Boot；U-Boot 完成完整外设初始化并启动内核，提供命令行。
  3. SPL 存在的原因？
    片内 SRAM 太小装不下完整 U-Boot，而 DDR 又必须先被初始化，因此需要一个能在 SRAM 中运行、只做 DDR 初始化与加载工作的小 loader。
  4. U-Boot 如何向内核传递参数？
    主要靠设备树：把 dtb 地址交给内核，其中 chosen 节点的 bootargs 携带命令行（root、console、init 等）。旧的 ATAG 方式已被废弃。
  5. 设备树在启动流程中的作用？
    U-Boot 把 dtb 传给内核，内核展开为 device_node 进而生成 platform_device，再按 compatible 匹配驱动。硬件改动不需要改 C 代码。
  6. 安全启动的实现原理？
    产线把公钥哈希烧进一次性可编程的 eFuse，每一级镜像用私钥签名，启动时由 BootROM/SPL 用公钥逐级验签，形成信任链，并可加入版本号防回滚。
  7. eMMC 与 NAND Flash 的差异？
    eMMC 内部集成控制器，自带 ECC 与磨损均衡，对主机表现为块设备；NAND 需要主机端处理坏块与 ECC，通常配合 UBI/UBIFS 使用。
  8. 根文件系统的挂载方式？
    常见三种：initramfs/initrd 作临时根加载驱动后再切换；直接挂载块设备上的 ext4/squashfs；网络场景用 NFS 根便于调试。

八、调试

  1. 内核崩溃如何定位？
    先保留日志（串口、pstore/ramoops、kdump），拿到 PC 指针与调用栈，再用 addr2line 或 gdb 结合 vmlinux/模块符号反查到源码行。
  2. oops 与 panic 的区别？
    oops 是非致命错误：打印现场后杀掉当前进程，内核通常还能继续跑；panic 是致命错误，内核立即停止，可按 panic_timeout 重启。
  3. 如何根据 PC 指针反查出错代码位置？
    用 addr2line -e vmlinux/module.ko 加地址，或 gdb 的 list *地址；内核配合 CONFIG_DEBUG_INFO 与 scripts/decode_stacktrace.sh 还原完整调用栈。
  4. printk 的日志级别与查看方式？
    分 0~7 级（KERN_EMERG 到 KERN_DEBUG），只有高于控制台阈值才打印，可通过 /proc/sys/kernel/printk 或 dmesg -n 调整；细粒度调试用动态调试 dyndbg。
  5. /proc 与 /sys 的区别？
    /proc 是内核内部状态与进程信息的动态视图；/sys 按设备模型组织 kobject 树，遵循"一个属性一个值"的约定，稳定性要求更高，不鼓励随意添加。
  6. debugfs 的使用场景？
    给开发者用的临时调试接口：导出寄存器、内部状态或调试开关，不承诺 ABI 稳定，因此不适合承载正式功能。
  7. ftrace / perf / strace / gdb 各自的适用场景？
    ftrace 看函数调用与 wakeup/irq 延迟；perf 做采样、PMU 与热点分析；strace 看系统调用；gdb/kgdb 或 crash+vmcore 做断点与现场分析。
  8. 内存泄漏如何检测？slab 信息如何查看？
    用 kmemleak 扫描疑似泄漏对象，KASAN 与 SLUB_DEBUG 查越界；总量看 /proc/meminfo 与 /proc/slabinfo，也可用 kmem tracepoint 追踪分配释放。
  9. devmem / i2c-tools 等工具的使用？
    devmem 直接读写物理地址以核验寄存器；i2cdetect/i2cdump/i2cget/i2cset 用来确认器件地址与寄存器值，常用来判断是软件配置还是硬件问题。

九、显示

  1. DRM 框架的组成部分？
    用户空间 libdrm、内核 DRM core、KMS（模式设置与显示管线）、GEM（显存分配管理）四大块；驱动实现 drm_driver 与各类 object 回调。
  2. CRTC / Encoder / Connector / Plane / Framebuffer 各自职责？
    Framebuffer 描述显存格式与 pitch；Plane 是图层，决定取哪块显存、位置与合成方式；CRTC 产生时序并扫描输出；Encoder 把 CRTC 信号转成 HDMI/eDP/DSI 等格式；Connector 代表物理接口，承载连接状态与 EDID。
  3. DRM bridge 的作用？
    表示链路上一个独立的转换器件（如 DSI 转 HDMI 的 LT9611），提供 attach、mode_valid、detect、get_edid、atomic_enable/disable 等回调，串接进显示管线。
  4. 显示时序（Hsync/Vsync/消影区）的含义？
    行同步与场同步信号，配合前后肩、同步宽度和有效区共同决定像素时钟与刷新率；消影区给电子束回扫留出时间，软件常用 Vsync 做页面翻转同步。
  5. MIPI DSI 的工作模式？
    分为 video mode（持续发送视频包）和 command mode（按命令写显示寄存器）；video mode 又细分为 non-burst、sync pulse、sync event 三种时序。
  6. MIPI CSI-2 与 DSI 的差异？
    CSI-2 是摄像头到 SoC 的单向接收链路，含虚拟通道与短包（帧起始/结束）结构；DSI 是 SoC 到屏幕的输出链路，通常还需要双向的 command 通道。
  7. buffer 如何在用户态与内核态之间流转？
    由内核分配或导入 dma-buf，用户空间通过 mmap 或 dma-buf fd 访问；显示侧用 GEM handle 转 prime fd 后做 atomic 提交，摄像头侧则通过 videobuf2 队列轮转。

十、网络

  1. mac80211 与 cfg80211 的关系？
    cfg80211 是内核无线配置与法规域子系统，向用户空间暴露 nl80211；mac80211 是 softMAC 协议栈，实现 802.11 的 MLME 与收发。fullMAC 驱动直接对接 cfg80211，不经过 mac80211。
  2. WiFi 驱动的注册流程？
    填充 ieee80211_ops 与能力，用 ieee80211_alloc_hw/register_hw 注册 wiphy，生成网络接口 netdev；再加载固件、初始化硬件后才可操作。
  3. 固件加载的流程？
    驱动 request_firmware 请求 /lib/firmware 下的固件文件，由内核的固件加载器（或用户空间协助）取回，再按芯片要求分段下载并启动。
  4. 扫描、连接、认证、关联的先后顺序？
    先扫描发现网络 → 认证（Open/SAE/共享密钥）→ 关联请求与响应 → 四次握手生成 PTK/GTK → 之后才能进行 DHCP 与数据收发。
  5. 数据收发路径？
    发送 netdev tx → mac80211 → 速率选择与聚合 → 驱动下发 → 固件发出；接收由固件产生中断或事件 → 构造 skb → ieee80211_rx → mac80211 → 上传协议栈。
  6. 省电机制如何实现？
    802.11 省电（PS-Poll、U-APSD、DTIM 间隔）、固件 beacon filter 与 WoWLAN、驱动及 bus 层 runtime PM 三者配合，在保持唤醒能力的前提下尽量关闭时钟与供电。

十一、功耗与电源管理

  1. suspend / resume 的完整流程？
    写 /sys/power/state → 冻结用户进程与内核线程 → dpm_suspend 系列阶段挂起设备 → 关闭非引导 CPU → 平台层进入低功耗；唤醒后按相反顺序恢复。
  2. dpm_suspend 的顺序如何保证？
    按设备注册与父子依赖关系排序，保证子设备先于父设备挂起，并分 prepare/suspend/suspend_late/suspend_noirq 等多个阶段，其中部分阶段可异步并行。
  3. 驱动的 suspend / resume 回调何时被调用？
    在系统挂起与恢复过程中由 PM 核心遍历设备调用，对应 dev_pm_ops 的各级回调；legacy 的 bus pm ops 也提供同名回调。
  4. runtime PM 的使用场景？
    设备空闲时自动进入低功耗、被访问时自动恢复，由 pm_runtime_get/put 与 autosuspend 延时控制；关键是正确处理上下文保存与恢复。
  5. wakeup source 的作用？
    标记设备的唤醒能力并统计唤醒事件，保证挂起过程中发生的唤醒不会丢失；配合 wakeup_count 读写检测"正在唤醒却要睡眠"的竞态。
  6. 系统无法唤醒的常见原因？
    唤醒中断未正确配置或未设为唤醒源、GPIO 极性错误、唤醒时电源域已被断电、固件未就绪、或某个设备驱动在 suspend_late/noirq 阶段卡住。

十二、Camera 与 V4L2

  1. V4L2 框架的核心对象有哪些？v4l2_device / video_device / v4l2_subdev / media_entity 的关系？
    v4l2_device 是顶层管理对象（挂在 bridge/ISP 驱动上），v4l2_subdev 代表一个具体视频器件（sensor、PHY、ISP），video_device 才是用户看到的 /dev/videoX；media_entity 是它们在拓扑图中的节点，用来建立连线。
  2. v4l2_subdev_ops 中 core / video / pad 三类 ops 各自的职责？
    core 负责初始化、日志、供电与事件订阅；video 负责 s_stream 启停、帧率的 get/set；pad 负责格式协商与枚举，即 enum_mbus_code、get_fmt、set_fmt、get_selection。
  3. media entity、pad、link 的作用？pipeline 如何构建与使能？
    pad 是输入或输出端口，entity 是功能模块，link 描述两者连接。先用 media_create_pad_link 建链，再用 media_entity_setup_link 使能链路、media_pipeline_start 启动整条 pipeline。
  4. media-ctl、v4l2-ctl、yavta 常用命令？如何用它们排查链路？
    media-ctl -p 打印拓扑、-l 建立链路、-V 设置格式；v4l2-ctl 列举格式、shown with --set-fmt-video 设置格式、--stream-mmap 抓帧；yavta 常用于 RAW 抓帧存盘。
  5. 格式协商流程？enum_mbus_code / get_fmt / set_fmt 分别在什么时候被调用？
    应用对 video 节点下发 S_FMT 时，驱动沿 pad 逐层反向调用下游 get_fmt/set_fmt 完成协商；enum_mbus_code 由应用在枚举阶段查询某个 pad 支持的 media bus 格式。
  6. MEDIA_BUS_FMT_* 是什么？为何要区分 sensor 输出格式与用户空间格式？
    它描述器件之间链路上的传输格式（如 SRGGB10_1X10），而用户空间拿到的是内存中的像素格式；二者由 ISP 或桥接器件转换，因此必须分开描述。
  7. try_fmt 与 set_fmt 的关系？crop / selection API 解决什么问题？
    try_fmt 只计算并返回结果而不改动状态，set_fmt 才真正写寄存器；selection API 用 CROP 与 COMPOSE 两个矩形描述裁剪与缩放窗口，支持硬缩放与 binning。
  8. v4l2_ctrl_handler 的作用？如何自定义 exposure / gain / hflip 控件？
    它统一管理一组 v4l2_ctrl，处理取/设值、范围校验与变更事件。自定义控件用 v4l2_ctrl_new_std 等接口注册，并在 s_ctrl 回调里写入寄存器。
  9. 如何通过 vblank / hblank 控制帧率？VTS、HTS 与帧率的关系？
    帧率等于像素率除以 VTS 与 HTS 的乘积，VTS 即有效行数加垂直消隐。改 vblank 就是改 VTS，驱动收到后会同步更新 VTS 寄存器，帧率随之变化。
  10. pixel_rate 与 link_freq 控件的区别？谁会去读它们？
    pixel_rate 是每秒像素数，link_freq 是各 MIPI lane 的链路频率。CSI 接收侧在配 PHY 与带宽时读取 link_freq，sensor 侧则用 pixel_rate 计算帧率与曝光。
  11. s_stream 里要实现什么？启流 / 停流的先后顺序要求？
    启流时写模式表、配 lane、写曝光增益、关测试图案，最后才打开数据流输出；停流时先停输出再下电。反过来会遇到无效帧或 I2C 挂死。
  12. videobuf2 的作用？dma-contig / vmalloc / dma-sg 三种内存方式的区别？
    videobuf2 统一管理缓冲区队列与入队出队。dma-contig 物理连续、适合 DMA；vmalloc 仅虚拟连续、不能做 DMA；dma-sg 用散列表，配合 IOMMU 使用。
  13. buffer 入队出队流程？REQBUFS / QBUF / STREAMON / DQBUF 的调用顺序？
    先 REQBUFS 申请缓冲，QBUF 把空缓冲交给驱动，STREAMON 开始采集，应用 DQBUF 取回填好的一帧，处理后再 QBUF 归还，最后 STREAMOFF 停止。
  14. sensor 驱动里 s_power 与 runtime PM 如何配合？上电时序谁保证？
    runtime PM 负责引用计数式的开关电源，真正的时序由 sensor 驱动保证：先供电，再开时钟，再释放复位或 powerdown 脚，等待若干毫秒后才做第一次 I2C 访问。
  15. 一颗 sensor 驱动中 I2C 与 MIPI CSI-2 各自承担什么职责？
    I2C 是控制通道，写寄存器配分辨率、曝光、启停；MIPI CSI-2 只负责高速传输图像数据。二者独立：控制面正常不代表数据面正常。
  16. 设备树里 sensor 节点的关键属性？endpoint、data-lanes、remote-endpoint 怎么配？
    compatible、reg（I2C 地址）、供电 regulator、时钟 xclk、复位与 powerdown GPIO；port 节点下的 endpoint 用 remote-endpoint 指向 CSI 接收端，data-lanes 写明使用的 lane 数量与编号。
  17. MIPI CSI-2 的 lane 数与带宽如何计算？lane 数与像素时钟的关系？
    所需速率约为分辨率×帧率×每像素位数再计上空消失额外的开销，再除以 lane 数得到单 lane 速率，必须落在 PHY 支持范围内并留一定余量。
  18. CSI-2 长包的数据结构？VC / DT / WC / ECC 字段的作用？
    包头为数据标识（虚拟通道 VC 加数据类型 DT）、字计数 WC 与 ECC 校验，随后是有效数据，最后是 CRC 校验；VC 区分多路逻辑流，DT 区分数据类型，WC 给出数据长度。
  19. CSI-2 的 LP / HS 状态机与时序参数如何确认？
    LP 是低速控制态，收包起止在 LP11；HS 是高速传输态。如果 RX 频繁报错，通常是 HS settle、LPX 等时序参数与 D-PHY 手册不匹配，需要调 PHY 寄存器或用示波器核对。
  20. D-PHY 与 C-PHY 的区别？
    D-PHY 用源同步差分时钟加若干数据 lane，双沿采样；C-PHY 用三线一组嵌入式时钟，无独立时钟线，单位引脚带宽更高，多用于高分辨率场景。
  21. RAW Bayer 数据进入 ISP 的路径？RK3588 ISP 管线由哪些部分组成？
    sensor 输出 RAW → CSI-2 RX 接收 → VICAP/ISP 做黑电平、镜头阴影、去马赛克、降噪与 3A 统计 → 输出 MP/SP 节点写入内存。RK3588 对应 rkisp 的 rawpath、mainpath 与 selfpath 几个 video 节点。
  22. 3A（AE / AWB / AF）由谁控制？用户空间在哪一层介入？
    统计信息由 ISP 硬件产生，算法一般在用户空间守护进程（如 rkaiq、libcamera）或固件中，算完后经 subdev 节点把曝光、增益写回 sensor。
  23. 测试图案（test pattern）怎么用？如何判断问题是出在 sensor 还是 MIPI 链路？
    打开 sensor 内置彩条图案：图案正常说明链路与 CSI 接收没问题，问题在光学或 ISP 处理；图案也异常则查 MIPI lane、带宽、时钟与供电。
  24. 多摄硬同步的实现方式？XVS / XHS / FSIN 外部触发的差别？
    主 sensor 输出帧同步信号给从 sensor，或接收外部同步信号。XVS/XHS 是行场同步输出，FSIN 则是把外部脉冲作为帧起始输入，从机据此对齐自己的曝光起点。
  25. 主从模式下如何保证两颗 sensor 同帧率、同相位？
    共用同一外部时钟，配置相同的分辨率与 VTS/HTS 以得到相同帧率，再用 FSIN 或主 sensor 的同步输出统一帧起始，必要时用寄存器微调延迟抵消固定相位差。
  26. 时间戳应取哪一时刻？为何用曝光中点而不是帧到达时刻？
    曝光中点最能代表该帧的物理时刻。帧到达时刻包含传输与中断、缓冲调度等抖动，误差大且不稳定，因此要用硬件帧起始加已知曝光时长校正。
  27. 多 sensor 与 IMU 如何统一时基？NTP / PTP / PPS 各自适用什么场景？
    NTP 毫秒级但依赖网络；PTP 靠硬件时间戳达微秒级，适合局域网；PPS 提供秒脉冲用于驯服本地时钟。嵌入式通常用 PPS 加本地计数器给各传感器打统一时基。
  28. 时钟抖动与走线长度对 MIPI 链路的影响？
    时钟抖动大会缩小接收端眼图的采样余量；lane 间长度不等会引入偏斜。表现为偶发 ECC/CRC 错误、花屏，通常需要等长布线、降速或调整 PHY 时序参数。
  29. 掉帧、帧率不稳的常见原因？
    应用取帧太慢导致队列耗尽、CPU 或内存带宽不足、ISP 处理跟不上；此外低照度下自动曝光拉长曝光时间也会把帧率压低。
  30. 图像偏绿偏紫、条纹干扰、花屏的常见原因？Bayer 顺序配错的判定方法？
    偏色多为 Bayer 顺序或白平衡、镜头阴影校正不对；条纹多为电源纹波与工频频闪（需配 50/60Hz 抗闪）；花屏多为链路带宽或 PHY 参数问题。判定 Bayer 可输出纯色或拍摄单色物体对比通道值与 RGGB 排列。
  31. probe 失败常见原因？如何确认是时钟、电源还是 I2C 地址问题？
    时钟未使能或频率不对、供电未打开、复位脚极性反了导致器件无应答、I2C 地址错、读出的芯片 ID 不匹配。可用万用表与示波器量电、i2cdetect 探地址，或看是否是资源缺失导致的延迟探测。

十三、传感器与 IIO

  1. 为什么传感器要用 IIO 子系统？相比自己写字符设备的优势？
    IIO 提供统一的采集与配置模型：标准 sysfs 属性、缓冲与触发机制、用户空间 libiio 直接可用，省去自造 ABI，也让上层应用可以跨厂商复用。
  2. IIO 不是总线，那它到底是什么层级的东西？
    它是位于具体总线（I2C/SPI）之上的设备类子系统，把五花八门的传感器抽象成统一的 Industrial IO 设备，向用户空间提供一致的访问方式。
  3. iio_dev 的核心结构体成员与作用？
    包含设备名与 modes（能力标志）、通道数组 channels、读写回调 info、以及当前绑定的 buffer 与 trigger 指针，是驱动的主体对象。
  4. IIO 通道（channel）如何描述？type / channel / scan_index / scan_type 的含义？
    type 指物理量类型（加速度、接近等），channel 区分同类第几个轴，scan_index 决定其在缓冲数据帧中的顺序，scan_type 描述存储位数、字节序、符号与位移。
  5. iio_chan_spec 中 modified、channel2、indexed 的区别？
    indexed 表示有编号的通道（如 accel_x），modified 表示用修饰维度进一步区分（如 accel_x + channel2 修饰的轴向），channel2 承载具体的修饰值。
  6. read_raw / write_raw 回调何时被调用？mask 参数怎么用？
    用户读写 sysfs 下的 raw、scale、offset、sampling_frequency 等属性时被调用。mask 是一个位掩码，指示当前要处理的是哪个属性（多个属性对应一个 mask 位）。
  7. sysfs 下 /sys/bus/iio/devices/iio:deviceX/ 各文件怎么来的？
    由 IIO 核心根据设备模式与通道定义、指定 type + mask 的属性自动生成，对应 sysfs Attributes；raw/scale/sampling_frequency 等名字由 IIO 核心固定。
  8. 单次读取（one-shot）与缓冲采集（triggered buffer）的区别与适用场景？
    单次读取是按需读一个属性，速度慢、延迟大；缓冲采集由 trigger 驱动连续采样并批量提交，适合高频、需要时间戳的场景，用 iio_readdev/libiio 读取。
  9. IIO trigger 的作用？为什么 IIO 不能直接循环采集？
    trigger 提供采样节拍（数据就绪中断、定时器、软触发等），每次触发采集一帧。没有 trigger 就无法确定采样时机，也就无法形成带时间戳的一批扫描数据。
  10. trigger 的类型有哪些？硬件 trigger 与 iio-trig-sysfs 的区别？
    包括基于中断的硬件 trigger、hrtimer 定时 trigger、sysfs 软 trigger 等。sysfs trigger 用于没有中断或临时调试的情况，精度与实时性都不如硬件 trigger。
  11. iio_trigger_generic_data_rdy_poll 的作用？
    用于在中断或上半部里通知 IIO：数据已就绪，让 IIO 框架调度下半部去读取并推送到缓冲。它是典型的"数据准备好"触发源。
  12. iio_trigger_poll 在上半部还是下半部调用？为什么？
    在上半部调用，它只负责把采样工作排入队列，并不做 I2C 读写等慢操作；真正的读取在 buffer 下半部的 pollfunc 里完成，从而保证中断快速返回。
  13. iio_triggered_buffer_setup 的四个参数各是什么？
    分别是 iio_dev 指针、下半部处理函数（真正去器件读取样本）、上半部（默认用 iio_pollfunc_store_time 打时间戳）以及 buffer setup ops（含 preenable/postdisable）。
  14. bottom half 中 iio_push_to_buffers_with_timestamp 做什么？
    把本轮采样的数据与时间戳写入 kfifo 缓冲，通知等待的读取者。若希望带硬件时间戳，则改用带 hardware timestamp 的版本。
  15. iio_pollfunc_store_time 的作用？时间戳从哪来？
    它是默认的上半部，在 trigger 触发瞬间用内核时间源记下时间戳，供下半部推送数据时使用，保证时间戳尽量接近真实采样时刻。
  16. buffer 的 preenable / postdisable 回调用来做什么？
    preenable 在缓冲使能前做硬件准备（配采样率、打开测量、清 FIFO），postdisable 在停止采集后关闭相关通路。它们是 enable/disable 时的钩子。
  17. 数据如何从内核缓冲传到用户空间？libiio / iio_readdev 怎么用？
    用户通过 IIO 字符设备读取缓冲（可用 select/poll 等待），libiio 封装了属性访问与缓冲流；iio_readdev 命令行工具可直接把数据录到文件。
  18. 用户空间 iiod / libiio 的工作原理？网络后端如何支持远程采集？
    iiod 作为守护进程在本地与设备交互，libiio 通过本地或网络后端连接它；网络后端让上位机远程访问板上的传感器，便于远程调试。
  19. 为什么 IIO 采集要用线程化中断？devm_request_threaded_irq 的上半部该做什么？
    取样本要通过 I2C/SPI 总线传输，耗时长且不能在原子上下文完成，因此交给中断线程去做。上半部只确认中断源、清中断，并调用 IIO 触发一次采样。
  20. 传感器数据的时间戳误差来自哪里？如何提高精度？
    误差来自中断响应延迟、总线传输耗时与软件打时间戳的滞后。提高精度的方法：尽量用硬件时间戳、让打时间戳的位置贴近真实采样时刻、必要时用定时 trigger 保证等间隔。
  21. 采样率如何配置？sysfs 的 sampling_frequency 与驱动的关系？
    由用户写 sampling_frequency 属性，驱动在 write_raw 回调里换算成器件支持的输出速率并写寄存器；注意实际值可能需要修约读回。
  22. IIO_CHAN_INFO_SCALE / OFFSET / RAW 的关系？为什么用户空间要自己换算物理量？
    物理量 = (raw + offset) * scale。把换算责任放到用户空间，让内核只提供线性系数，避免不同单位制与浮点运算进入内核。
  23. 接近传感器（如 hx9023s）的通道配置与校准流程？
    先按数据手册配置通道与采样参数，再在无障碍条件下读一次基线作为 offset，然后用标准目标物在各距离测试确认读数曲线，必要时做串扰与温度补偿。
  24. 多通道数据如何保证来自同一时刻？
    靠同一 trigger 的一次扫描：所有启用通道由一次采样同时读出并打同一个时间戳，存入同一条扫描记录。
  25. regmap 在传感器驱动中的作用？为何 IIO 驱动普遍使用 regmap？
    统一 I2C/SPI 寄存器读写，并提供缓存、范围检查与 debugfs 导出。传感器以寄存器访问为主，因此 regmap 几乎成为标配。
  26. IIO_TRIGGER 与事件（IIO_EV_TYPE_* / iio_push_event）的区别？中断阈值告警如何实现？
    trigger 用于批量数据采集；事件则是单个异步通知（越阈值、方向变化、接近物体等），用 iio_push_event 推给用户空间读取。
  27. IIO 与 hwmon 的边界？什么设备该放 IIO、什么该放 hwmon？
    hwmon 面向慢速的系统监控类器件（温度、电压、风扇），强调可读的限值告警；需要高采样率、时间戳、多轴数据的就放 IIO。
  28. IIO 与 input 子系统的边界？加速度计为什么有的走 input 有的走 IIO？
    input 用于人机交互事件（按键、屏幕旋转上报），语义是离散事件；IIO 用于带时间戳、可缓冲的连续采样。早期 Android HAL 常用 input 方式上报加速度，现在倾向 IIO。
  29. 传感器驱动的 suspend / resume 需要注意什么？runtime PM 如何配合？
    挂起前停止缓冲与采样，必要时保存器件上下文；恢复时按 buffer setup ops 重新执行使能流程，清掉残留 FIFO，避免第一帧数据错位。
  30. 读数漂移、噪声大、偶发丢数的常见原因？
    电源纹波与地线干扰、安装应力与温漂、采样率设置不当造成混叠、超出量程；此外用户取数太慢也会导致缓冲溢出丢帧。
  31. 如何在不改动驱动的情况下验证传感器硬件是否正常？
    用 i2cdetect/i2cdump 核对器件地址与寄存器值，再用 iio_info、直接读 raw/scale 或用 iio_readdev 观察数据是否随物理量变化而变化。
