两个必须记住的点：

  • **”use read to push write”**：PCIe 的 memory write 是 posted 的，切窗口后必须补一次读来保证这次写真的到达设备；否则读回来的是旧窗口内容——表现为”读到的寄存器值永远是别的模块的”。这条路径上空转严重的话，性能热点会落在 __mt7925_reg_addr() 而不是业务代码。
  • backup_l1/backup_l2：窗口是全局共享资源，每次访问前 mt7925_reg_remap_restore() 把上一次的值写回去，避免踩掉别人。这也是 struct mt792x_dev 里专门留这两个字段的原因。由此能看出这条路径隐含状态、不可并发，上层访问寄存器时靠 mt76 的 mutex 串行化——写别的驱动时若也采用”窗口切换”方案，锁的范围必须覆盖”切换 + 读/写”全过程。

调试提示：debugfs 的 regval 走的是 MCU 命令（mt7925_mcu_regval()），不是这条 mmio 路径。两者可达地址、时序都不同，不要拿 regval 的结果跟 mmio 读出来的互相印证。

四、中断：上半部 → tasklet → NAPI → 重新开中断

这一节是 PCIe 驱动最核心的部分，也是”能不能写出高吞吐驱动”的分水岭。

4.1 为什么只有 1 个中断向量

现代做法是”每队列一个 MSI-X 向量 + 多组 NAPI”，很多高性能网卡就是这么干的。MT7925 反过来：只要 1 个向量，所有 ring 共用一个中断源，靠软件在下半部按状态寄存器分流。原因是：

  1. 硬件中断源数量有限，MT_WFDMA0_HOST_INT_STA 里一个 bit 代表一类事件；
  2. 用 tasklet + 每 ring 一个 NAPI 的结构把”分流”从硬件搬到软件，反而更好调试（一个 IRQ、一个 trace 点：trace_dev_irq）。

代价：单核上一个 tasklet 串行走完分流，中断潜伏期受 tasklet 调度延迟影响。这也是 MT7925 在高 PPS 场景（小包 flood）里延迟抖动的一个来源。

4.2 三层结构总览

“关中断 → 处理 → napi_complete 之后再开”是这条链路的灵魂：设备在 NAPI 工作期间被屏蔽，避免”包还没收完又来中断”，同时下半部不需要自旋等待。

4.3 上半部：mt792x_irq_handler()

标准 PCIe 驱动上半部的教科书要点，它全占：

  • 只做最小的事：不读 ring、不碰 skb，只做”确认中断属于我 → 关中断源 → 调度下半部”。
  • 共享中断必须判断 ownership：这里用 MT76_REMOVED / MT76_STATE_INITIALIZED 两个状态位。注意它在判断之前已经把设备侧中断关了——因为”卸载过程中飘进来的中断”恰恰是最需要立刻静音的情况。
  • **不是自己的中断必须返回 IRQ_NONE**，否则共享 IRQ 的核会以为你在处理，长时间下来会触发 irq N: nobody cared 告警。

4.4 下半部（tasklet）：分流到 NAPI

几个通用 PCIe 驱动里同样适用的要点：

  • **清中断的方式是”读状态 → 原样写回”**（MT_WFDMA0_HOST_INT_STA），典型的 W1C 寄存器用法，和 IRQ chip 里 ack = write(status) 一个道理。
  • 两级中断使能：设备侧 MT_WFDMA0_HOST_INT_ENA（irq_map->host_irq_enable）管”要不要拉中断”，固件侧 MT_MCU2HOST_SW_INT_ENA / MT_MCU_CMD 是纯软件的”固件有事找主机”通道。写这类”PCIe + 板载 MCU”设备驱动的通用套路就是 pin 中断 + 软件 doorbell，只 ack 一边必然漏事件。
  • 先 mask 再 schedule：mt76_set_irq_mask(..., mask, 0) 在 napi_schedule() 之前执行，防止 NAPI 还没起来又进来一个 hardirq 重新排 tasklet，形成 mask 竞态。
  • 一次中断可以同时唤起多个 NAPI（收数据 + MCU 事件），这就是”单向量多队列”里软件分流的具体形态。

5.3 ring 的寄存器三件套与 kick

每个 ring 通过一组 mmio 寄存器控制，mt76 抽象成 Q_READ/Q_WRITE：

PCIe DMA ring 的通用规律在这里体现得很清楚：

  • cpu_idx = 生产者指针，软件填完描述符后再通知硬件；
  • dma_idx = 消费者指针，由硬件写回，软件只读；
  • head/tail/queued 是软件侧镜像，用来判断 ring 空/满。

理解这三点，任何 PCIe DMA ring（NVMe、以太网卡、通用 DMA engine）都是同一套逻辑，只是寄存器名不同。

5.4 一次 TX：从 skb 到”写 cpu_idx”

值得对比自身项目的地方：

  • 批量 kick：mt76_txq_send_burst() 先把 N 个 skb 塞进 ring，最后才 kick 一次。这是高 PPS 场景的标准优化——每包一次 mmio 写会很贵。
  • TXWI 走 dma 映射缓存池：mt76_alloc_txwi() 预映射一块 txwi 内存并挂进 txwi_cache 链表（MT_DRV_TXWI_NO_FREE 表示完成时不用回收），本质是”hot path 不做 dma_map/unmap”。
  • ring 满 ≠ token 满：ring 满会返回 -ENOMEM（q->queued + (nbuf+1)/2 >= q->ndesc - 1）；而 token（.token_size = 8192）是另一层流控，mt76_token_consume() 抢不到就把 TX 阻塞住（__mt76_set_tx_blocked）。所以”发不出去但也不报错”先怀疑 token 耗尽，而不是 ring 满。

5.5 一次 RX：预填充 → 回填 DONE → napi_build_skb

RX ring 是驱动先把空 buffer 挂满，硬件搬完数据后置 DMA_DONE：

两个标配技巧：

  1. **page_pool + napi_build_skb()**：DMA buffer 直接变成 skb 数据区，零拷贝；skb_mark_for_recycle() 让 skb 释放时回到 page_pool 而不是伙伴系统。现代网络驱动标配。

六、PCIe 电源管理：ownership 握手、ASPM、suspend/resume

PCIe 无线设备比普通 PCIe 设备多一层复杂度：MCU 固件也在争这块芯片的控制权。

6.2 ASPM：标准做法 vs mt7925

标准做法只有一行 pci_disable_link_state()，mt7925 之所以要写几十行，是因为下游设备和它的上游口必须一起关：

可直接抄的经验：ASPM 是链路两侧协商的，pci_disable_link_state() 只能禁一侧。遇到”设备偶尔卡死 / 掉链路 / 唤醒失败”，用 lspci -vvv 同时看设备和上游口的 LnkCtl: ASPM 字段。mt76_pci_aspm_supported() 只是同一个读过程的 bool 版本。

6.3 suspend / resume：顺序不能乱

resume 完全反向：drv_pmctrl → mt792x_wpdma_reinit_cond → 开 MT_PCIE_MAC_INT_ENABLE → mt76_connac_irq_enable → 置 DMA 使能 → enable worker → local_bh_disable() 包住逐个 napi_enable + napi_schedule → mt76_connac_mcu_set_hif_suspend(false) → 恢复 deep sleep 设置。

这是 PCIe suspend 的教科书顺序：

停生产者（work/NAPI） → 等 DMA 空闲 → 关 DMA 使能 → 关中断源 → synchronize_irq() + tasklet_kill() → 再交给电源/固件

少了 synchronize_irq() / tasklet_kill()，就会出现”刚 resume 就踩到已经释放的 NAPI/队列”的经典崩溃。resume 侧用 local_bh_disable() 包住 enable+schedule，则是保证 NAPI 起来那一刻不会被软中断抢占导致顺序错乱。

七、卸载：remove / shutdown 与 devres 边界

可提炼出的通用卸载顺序：

  1. 停掉所有异步/延时工作（cancel_*_sync），保证没有人在访问寄存器；
  2. 先掐断数据源（unregister → napi_disable），让上层不再下发新请求；
  3. 释放自己管理的业务资源（这里的 token / MCU 队列）；
  4. 设备安静下来之后再拆 DMA 和中断（顺序不要反：先 DMA cleanup，再 free IRQ）；
  5. 设置一个”我已死”的状态位（MT76_REMOVED），让可能还在飞行中的 ISR 立刻退出；
  6. 最后交给 devres 与 pci_free_irq_vectors() 收尾。

重点记住 set_bit(MT76_REMOVED, ...) 这行：共享 IRQ 下，这个状态位是避免 ISR 与 teardown 并发竞态的唯一手段。没有它就可能出现”ISR 跑在已经释放的 dev 上”。

PM 停生产者 → 等 DMA idle → 关 DMA → 关中断 → synchronize_irq/tasklet_kill → 交给固件 mt7925_pci_suspend/resume
恢复后 假设 ring 指针失效，必要时重置 DMA mt792x_wpdma_reinit_cond
卸载 掐数据源 → 释放业务资源 → 拆 DMA → 拆中断 → devres 收尾 mt7925e_unregister_device + mt7925_pci_remove

读完这一篇再看第 03~08 篇的固件、MAC、mac80211、数据通路内容，可以只把它们当成”跑在这套 PCIe 骨架之上的软件”，不用再关心总线差异；反过来，想把这套骨架迁移到别的 PCIe 设备上，也只需要替换 probe 里那几项资源、”CPU/DMA 索引 + 描述符”的具体寄存器名，以及中断屏蔽寄存器的位数。
