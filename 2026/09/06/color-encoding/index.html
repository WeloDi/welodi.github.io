色彩编码格式

2026-09-06

〇、像素的”颜色”加工

一张相机的彩色图，不是 sensor”直接拍出来的彩色”，而是经过多级处理：

  1. RAW 图像的每个像素只有 1 个通道值（只感 R 或 G 或 B 一种光），不是”彩色像素”
  2. 同一种”视觉颜色”，在不同阶段叫不同格式：sensor 端 = Bayer 相位 + 位深；ISP 输出 = RGB/YCbCr + 位深 + 色度抽样；内存里 = V4L2 fourcc

一、CFA 与 Bayer：颜色是怎么被”抽样”的

单色 sensor 只有亮度信息。要出彩色，就在每个像素上贴一片微型滤色片（CFA，Color Filter Array），让该像素只感红、绿、蓝中的一种光。

主流是 Bayer CFA，2×2 为一个周期：

  • 绿占 1/2：人眼对绿色最敏感（也是 SNR 最高的通道）
  • 红、蓝各占 1/4

二、RAW 的”位深”与”值”：它们还不是颜色

RAW 值 = 该像素对应通道的光强（经过 ADC 量化、模拟增益、黑电平偏移）

  • 黑电平要减掉：sensor 的”零光”输出通常不是 0（留余量防 ADC 底部噪声），demosaic 前若不做黑电平校正，暗部会发灰、偏色

三、从 Bayer 到 RGB：demosaic 与 ISP 的调色链

sensor 送出的 Bayer RAW 要变成人眼能看的图，ISP 至少要干这几件事：

步骤 做什么 出错表现
demosaic 用邻居像素插值，把每个像素补成 R/G/B 三通道 假彩、拉链纹、边缘彩边
白平衡 WB 给 R/B 通道乘增益，让灰卡拍出来 R=G=B 整幅偏蓝/偏橙
CCM 3×3 矩阵，把 sensor 滤色片响应”矫正”到标准色度 颜色发假、饱和过度
gamma 亮度的非线性编码，匹配显示特性 整体发灰或对比怪异
  • demosaic 是全彩的关键一步：Bayer 每个像素只有 1 通道，所谓”1600 万像素相机”实际 sensor 上就是 1600 万个单通道感光点，全靠插值合成
  • CCM 是偏色调试第一站：sensor 的滤色片响应不等于标准 RGB，各家 ISP 都带 3×3 CCM 表。如果一张图颜色整体不对（不是”红蓝对调”那种结构性错误），先查 CCM / WB，别去 sensor 侧瞎调模拟增益

四、YUV格式

RGB 面向显示：显示器就是三个子像素叠光。YUV 面向传输与压缩。

4.1 为什么不用 RGB 直接传输

RGB 三个分量同等重要，砍谁都明显偏色；YUV 把画面拆成 1 路亮度（Y）+ 2 路色差（U/V），好处：

  1. 人眼对亮度敏感、对色度迟钝 → 色度可以降采样省带宽（见 4.3）
  2. H.264/H.265 等编码本就围绕亮度+色差工作
  3. 兼容黑白显示的历史需求（老电视只取 Y 一路）

4.2 YUV 的分量与名词

分量 含义 计算本质
Y 亮度（就是灰度图） 各 RGB 按权重加权
U（Cb） 蓝色差，数字化叫 Cb B − Y，蓝色越多差越大
V（Cr） 红色差，数字化叫 Cr R − Y，红色越多差越大
  • 说”YUV”时绝大多数指 YCbCr：JPEG、MPEG、H.264/H.265、sensor 的 YUV 输出都属于 YCbCr 一族；YPbPr 是模拟分量，结构相同、系数略异。驱动/ISP/FFmpeg 打交道的基本都是 YCbCr。
  • 色差以 Y 为基准（B−Y、R−Y），所以”亮度 + 两张色差图”就能无损还原彩色：解码端把 Y 加回色差即可。

4.3 YUV 采样

色度在空间上抽稀是 YUV 省带宽的关键：人眼对色度不敏感，Cb/Cr 不必每个像素都带，按几个 Y 共享一组色度分成三档：

YUV 4:4:4
完全取样，每个像素都有独立的 Y/U/V 值

YUV 4:2:2
色度水平减半（水平方向每两个像素共用一对U/V值）

YUV 4:2:0
色度水平+垂直都减半（相邻的4个像素（2 * 2）共用一对U/V）
